# 从安装到第一次成功读取

## 选择工具路径

推荐：支持Skill且已提供浏览器工具的AI助手。Skill文件和浏览器连接是两项独立配置。

1. 将本Skill整个目录复制到宿主的技能目录，保留references、assets、agents。让助手确认能加载本Skill，而非只读README。
2. 在宿主的工具或插件设置中启用其支持的浏览器能力。具体菜单随产品版本变化，以该宿主当前文档为准；不要假设安装Skill就自动获得浏览器接口。
3. 用同一浏览器打开自己的小红书收藏夹；登录由用户完成。把链接交给助手并指明目标文件夹。不要复制Cookie或验证码到聊天、文件或仓库。
4. 先发送下面的预检请求，验证列表和正文读取成功后再批量整理。

> 使用 $xiaohongshu-travel-planner。先只检查我提供的收藏夹：确认文件夹名称与显示数量，读取当前可见标题，打开一篇旅行笔记并概括正文。分别告诉我列表、正文、图片和视频是否实际读到。先不要生成攻略，也不要修改收藏。

通过条件：正确识别文件夹、读到列表、打开一个匹配标题的详情并得到正文。图片/视频未读可以标为未验证，不算正文测试失败。只出现页面标题或加载成功提示不算通过。

## 可选：已有OpenCLI的环境

这不是主流程必需依赖，也未在本版本做端到端验证。若宿主允许该工具，先按[OpenCLI官方项目](https://github.com/jackwener/OpenCLI)配置浏览器扩展，然后用当前版本的 `opencli doctor` 检查连接、`opencli xiaohongshu --help` 发现实际支持的命令。不得凭空编造收藏夹导出命令；无专用命令时只使用工具当前文档支持的浏览器操作。公司内部CLI不是公开版依赖。

## 常见停点

| 停在哪 | 下一步 |
|---|---|
| 助手根本没有浏览器工具 | 配置宿主浏览器能力；或使用用户提供的导出材料，明确不是在线抓取 |
| 找不到用户登录的页面 | 核对浏览器实例/配置文件，不能把另一个浏览器登录当作已同步 |
| 能看到收藏夹但读不到正文 | 检查详情是否打开、页面限制；保留列表成果，标记失败，不从标题生成正文 |
| 图片里才有路线 | 实际查看对应图片；无图像能力则标记未解析 |
| 验证码或访问限制 | 用户在浏览器处理必要登录/验证，不绕过限制 |

重复错误按browser-reading.md处理。当前Codex桌面浏览器路径有小范围实测；其他宿主和OpenCLI路径须在使用者环境预检。
