# 收藏夹读取、覆盖与续做

1. 记录目标文件夹显示名称、显示总数（看不到写null）、读取时间、使用工具与验证范围。真实链接仅存用户本地工作资料，不进入公开仓库。
2. 滚动列表，每批记录笔记ID、标题和当前可见来源。按ID去重；缺ID时用去掉临时访问参数后的稳定链接作键，不能只凭标题合并。实际打开使用当前页面提供的完整链接，临时参数仅在会话中使用。
3. 只有明确看到末尾并完成一次无新增的确认，或实际列表与显示数量一致且无其他分页迹象，才记录列表完成。连续滚动无新增只能说明可能卡住，不能单独证明全量。总数变化时记录变化，重新对账。
4. 区分“重复卡片”和“重复地点”：前者不增加笔记数，后者保留独立笔记及来源，只在地点层合并。推荐流不能记作收藏。
5. 每篇保存一种处理状态：pending待读、read已读正文、blocked受限、excluded按用户条件排除。已读正文不代表图片/视频已读，另记media状态。对blocked/excluded填写原因；不要用跳过掩盖读取失败。
6. 分批落盘reading-progress.json与来源表；恢复时先核对文件夹与上次状态，再继续pending和有条件恢复的blocked，避免重读全部。页面变化可能需重新找链接，不复用旧节点编号。
7. 结束时分别报告显示总数、去重列表数、正文读取数、未读/受限/排除数、媒体覆盖。状态之和应等于去重列表数；未知总数不计算全量百分比。列表齐全不等于详情齐全，正文齐全不等于媒体齐全。
8. 来源内容提炼为地点、分店、体验和作者说法，执行信息另查官方。只使用已读证据排程，受限情况下可以交付部分攻略，但必须说明缺口。

progress模板是手工/模型维护的数据约定，不是已经实现的自动抓取程序；写完须核对字段及数量。不得存储Cookie、验证码、浏览器快照全文或临时签名URL。

具体字段见[虚构进度示例](progress-example.md)。
